# GDB 常用命令

下面列出我常用的 GDB 命令，供大家参考。对于有简写的命令，先给出完整的命令，然后再给出简写的命令。

## 选择调试目标

```
file <文件名>
```

## 运行

```
run <参数>
```

## 退出

```
quit
q
```

## 设置断点

在当前行设置断点：

```
breakpoint
b
```

在指定行设置断点：

```
breakpoint <行号>
b <行号>
```

## 删除断点

在当前行删除断点：

```
clear
```

在指定行删除断点：

```
clear <行号>
```

删除所有断点：

```
delete
d
```

## 显示源码

显示当前位置附近的源码：

```
list
l
```

显示指定行号附近的源码：

```
list <行号>
l <行号>
```

## 运行到断点

```
continue
c
```

## 显示变量的值 / 表达式求值

```
print <变量名 / 表达式>
p <变量名 / 表达式>
```

或：

```
display <变量名 / 表达式>
disp <变量名 / 表达式>
```

>[!TIP]
> `print` 与 `display` 的用法基本相同，区别在于使用 `display` 显示的表达式会被加入一个“自动显示列表”中，之后每当程序暂停时，GDB 会自动显示它们（前提是该表达式所引用的局部变量还在作用域内）。因此，如果你需要连续追踪一个表达式的变化，使用 `display` 命令更方便。

## 查看信息

```
info <信息>
i <信息>
```

### 查看所有局部变量

```
info local
i local
```

### 查看函数参数

```
info args
i args
```

### 查看已设置的断点

```
info break
i break
```

### 查看全部寄存器

```
info registers
i reg
```

### 查看单个寄存器

```
info register <寄存器名>
i reg <寄存器名>
```

### 查看栈帧信息

```
info frame
i frame
```

## 打印函数调用栈

```
backtrace
bt
```

## 逐行执行代码

执行一行：

```
next
n
```

执行指定行数：

```
next <行数>
n <行数>
```

## 执行一条机器指令

```
nexti
ni
```

> [!TIP]
> 以上所有的命令，在遇到函数调用时，会直接执行整个函数体，不会停在函数内部。如果需要停在函数内部，可以使用 `step` 命令。

## 逐行执行代码（不跳过函数体）

执行一行：

```
step
s
```

执行指定行数：

```
step <行数>
s <行数>
```

## 执行一条机器指令（不跳过函数体）

```
stepi
si
```

## 反汇编

```
disassemble <函数名 / 内存地址>
disas <函数名 / 内存地址>
```

> [!TIP]
> 当指定内存地址时，`disassemble` 还能告诉你它位于哪个函数内。但是，该命令只能反汇编位于可执行文件内的函数，并不能反汇编任意地址，对于 JIT 编译器动态生成代码之类无能为力。要反汇编任意地址，可以使用 `x` 命令。

## 自动显示下一行代码的反汇编

```
set disassemble-next-line on
```

## 设置反汇编语法（仅限 x86）

在 x86 平台上，有两种流行的汇编语法：Intel 和 AT&T。默认情况下，GDB 使用 AT&T 语法，它也是 Unix/Linux 世界事实上的标准。如果你更喜欢 Intel 语法，可以使用下面的命令：

```
set disassembly-flavor intel
```

## 显示内存区域的内容

`x` 是一个非常强大但也较为复杂的命令。`x` 就是它的全写，没有简写。基本用法如下：

```
x <起始地址>
```

要更详细地控制，可以使用 `x` 命令的选项：

```
x/<长度><格式><单元大小> <起始地址>
```

单元大小：

- `b`：字节
- `h`：半字（2 个字节，16 位）
- `w`：字（4 个字节，32 位）
- `g`：巨字（giant word，8 个字节，64 位）

常用格式：

- `x`：十六进制
- `d`：十进制有符号
- `u`：十进制无符号
- `t`：二进制
- `s`：字符串
- `i`：机器指令，可以用于代替 `disassemble` 反汇编任意地址。当使用这一格式时，单元大小会被忽略，长度代表指令数量

例如，将内存地址 0x12345678 处的 128 字节（64 个单元）作为 16 位有符号整数打印：

```
x/64uh 0x12345678
```

反汇编 0x12345678 处的 10 条指令：

```
x/10i 0x12345678
```

## 设置观察点（watchpoint）

观察点是一种特殊的断点，在指定的表达式的值发生变化时触发。

设置方法：

```
watch <变量名 / 表达式>
```

如果要监视指定的内存地址，需要一些变通，例如：

```
watch *(int*)0x12345678
```

> [!TIP]
> 观察点分为两种：硬件断点和软件断点。硬件断点性能更好，但需要硬件支持，且数量存在上限（根据 CPU 架构而定，在 x86 上是 4）。默认情况下，GDB 使用硬件断点，如果硬件不支持或数量太多，会自动切换到软件断点。

## 设置捕捉点（catchpoint）

捕捉点是一种特殊的断点，在指定的事件发生时触发

设置方法：

```
catch <事件>
```

对于 C/C++ 来说，常用的事件包括：

- `throw`：C++ 异常抛出
- `catch`：C++ 异常捕获
- `load`：动态链接库加载
- `unload`：动态链接库卸载
- `exec`：`exec` 系统调用
- `fork`：`fork` 系统调用
- `vfork`：`vfork` 系统调用
- `syscall`：其他系统调用

> [!TIP]
> 设置 watchpoint 和 catchpoint 需要使用专门的命令，但管理命令（查看、删除等）与普通断点是一样的。
