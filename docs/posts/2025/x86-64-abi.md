# x86-64 调用约定及 ABI 总结

> 作者声明：此为个人学习心得，不保证准确！

x86-64 Windows 上仅存在一种统一的调用约定：`__fastcall`。它的 32 位版本和 64 位版本略有区别，下面我们只讨论 64 位版本。

## 1. 参数的传递方式

`__fastcall` 将部分参数通过寄存器传递，比起纯粹使用栈快一些，这也是它得名的原因。

前4个参数中的整数分别通过寄存器 `rcx`、`rdx`、`r8`、`r9` 传递。

前4个参数中的浮点分别通过寄存器 `xmm0`、`xmm1`、`xmm2`、`xmm3` 传递。

剩余参数通过栈传递，按照**从右到左**的顺序压入栈中。

### 示例：

```c
int f(int a, double b, int c, float d, int e, float f);
// a - rcx, b - xmm1, c - r8, d - xmm3, f和e在栈中（先压入f，再是e）
```

## 2. 返回值的传递方式

整数返回值通过 `rax` 传递，浮点数返回值通过 `xmm0` 传递。还是以刚刚的函数为例，它的返回值将在 `eax` 中（因为 `int` 是 32 位）。

## 3. 易失性与非易失性寄存器

你可能已经注意到了，有一些寄存器的值在函数调用前后会改变。毫无疑问，这是因为被调用的代码需要使用它们。可以由被调用者随意更改的寄存器称为**易失性（volatile）寄存器**。寄存器 `rcx`、`rdx`、`r8` 至 `r11` 以及 `xmm0` 至 `xmm5` 为易失性寄存器。被调用函数可能修改它们的值，因此，其中若包含有用的信息，调用者必须在调用前自行保存它们。

被调用者不可随意更改的寄存器称为**非易失性（nonvolatile）寄存器**。寄存器 `rbx`、`rbp`、`rdi`、`rsi`、`rsp`、`r12` 至 `r15` 以及 `xmm6` 至 `xmm15` 为非易失性寄存器。你可以放心地将重要的数据存放在其中。假如被调用者需使用这些寄存器，则必须先保存这些寄存器原本的值，并在使用完后还原它们。

## 4. Prolog 与 Epilog

一个典型的函数一般从前往后分别由 prolog、body、epilog 三部分组成。其中 body 部分包含了函数的主要逻辑。可以简单理解为：当使用 C 语言编写程序时，你所编写的代码就是 body。Prolog 与 epilog 一般是由编译器自动生成的，但它们同样很重要。

Prolog 为函数的 body 部分做准备工作。它一般会执行以下操作：
  1. 将通过寄存器传递的参数保存至调用者提供的 *shadow space*
  2. 为本函数的局部变量分配栈空间
  3. 保存本函数将要修改的非易失性寄存器值
  4. 为它将要调用的其他函数分配 *shadow space*

Epilog 在函数的 body 部分结束后进行清理。它一般会执行以下操作：
  1. 清理为其局部变量分配的栈空间，以及为其他函数分配的 *shadow space*
  2. 将修改过的非易失性寄存器恢复为其原本的值
  3. 返回至调用者

上面提到的 *shadow space* 将会在稍后详解。

在学习 C 语言时，你应该已经知道了，局部变量是分配在栈中的，并在其作用域结束后失效。现在你知道这背后的原理了：prolog 负责为局部变量分配栈空间，而 epilog 负责清理它们。

至于“分配”的方法，也很简单，只需一行汇编代码即可：

```asm
sub rsp, <局部变量所需的空间之和>
```

`rsp` 寄存器指向栈顶的元素。在 x86 架构中，**栈从高地址向低地址“增长”**，因此当栈的内容增多时，`rsp` 的值反而会减小。

“清理”的方法则是反过来，将 `rsp` 的值增加即可：

```asm
add rsp, <局部变量占用的空间之和>
```

由于一些技术原因，Windows x86-64 ABI 要求 `rsp` **在函数的body内保持不变**。`push` 和 `pop` 指令会修改 `rsp`，因此也不能使用。对于栈的操作，包括压入与弹出，以及前文所述的分配和清理，必须在 prolog 与 epilog 内进行。

下面是一段 C 代码：

```c
void a(int);

void f(void) {
    int n;
    n = 50;
    a(n);
}
```

以及它编译得到的汇编代码：

```asm
f():
        sub     rsp, 40 ; 分配空间
        mov     dword ptr [rsp + 36], 50  ; 给局部变量 n 赋值 50
        mov     ecx, dword ptr [rsp + 36] ; 将局部变量 n 作为参数传递给 a。因为 int 是 32 位，所以这里使用了 32 位寄存器 ecx
        call    a(int)
        nop
        add     rsp, 40 ; 清理空间
        ret
```

可以看到，函数中引用局部变量时，实际上使用的是它相对于 `rsp` 的偏移量，而不会使用 `push`、`pop` 等指令。

## 5. Shadow Space

刚刚的代码中有这样一行：`sub rsp, 40`。我们都知道 `int` 类型占 4 个字节，按道理来说，一个 `int` 型的局部变量 `n` 只需 4 字节即可存下，40 这个数是怎么来的呢？

这就涉及到了前文提到的 *shadow space*（也叫 *home space* 或 *spill space* ）。假设函数 A 需要调用函数 B，则 A 必须在**自己的 prolog 中**为 B 保留一块“shadow space”。

Shadow space 有什么用呢？

如前文所述，`__fastcall` 调用约定将部分参数通过寄存器传递。然而，寄存器的值可能在后面的代码中被修改。这给调试工作带来了极大不便：寄存器被覆盖后，将无法得知原本传递给函数的参数。

此时 shadow space 便发挥了用处：编译器会在**被调用函数**的 prolog 中生成代码，将参数复制到 shadow space 中，以便后续调试。当编译器被设置为发布（release）模式，或者启用优化时，将不会生成上述代码，以改善性能。此时 shadow space 没有用处，但仍然必须存在。

此外，shadow space 也被用于简化 `printf` 等变参函数的实现。

Shadow space 的大小始终固定为 **4（寄存器的数量） × 8（每个8字节） = 32 字节**。即使函数接受的参数数量小于 4，甚至不接受任何参数，也是如此。假如一个函数需调用多个函数，它并不需要分配多块shadow space，所有被调用函数共用同一块 shadow space。

但是，即使加上了 shadow space，4 + 32 还是不等于 40 啊！这是因为，在 x86-64 中，栈需要对齐到 16 字节的倍数。在代码执行前，栈原本是对齐的。执行函数 `f()` 时，`call` 指令将返回地址（64 位，8 字节）压入栈中，从而破坏了对齐。8（返回地址）+ 4（局部变量）+ 32（shadow space）= 44，因此还需额外的 4 个字节以将栈对齐到 48 字节。函数 `f()` 在其 prolog 中分配的 40 字节，实际上是被这样使用的：

```
|------------------------|
|                        |
|     返回地址（8字节）   |
|                        |
|------------------------|   <- 执行sub rsp, 40前，原本的rsp
| 对齐（4字节，未实际使用）|
|------------------------|   <- rsp + 36
|    局部变量 n（4字节）  |
|------------------------|
|                        |
|                        |
|                        |
|  shadow space（32字节） |
|                        |
|                        |
|                        |
|------------------------|   <- rsp
```
